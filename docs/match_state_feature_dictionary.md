## 1. Schema Conventions & Role Classifications

Every row represents one atomic delivery transition `(match_id, innings, innings_ball_num)` ordered strictly ascending (`200,999` rows across `867` matches; the `16` zero-delivery abandoned matches exist at match/regime metadata grain only).

- **Data Types (Nullable Pandas / Parquet Contract):**
  - `Int64`: nullable 64-bit integer preserving `pd.NA` without float coercion
  - `Float64`: nullable 64-bit IEEE float preserving `pd.NA`
  - `boolean`: nullable boolean (`True` / `False` / `pd.NA`)
  - `string`: nullable UTF-8 string
  - `date`: ISO calendar date (`YYYY-MM-DD`)
- **Mandatory Four-Way Role Classification:**
  1. **`identifier`**: Join keys, sequence keys, participant IDs, display labels, or split keys. Never fed raw as linear numeric magnitudes; only safe low-cardinality entity IDs (`comp_id`, `venue_id`, `batting_team_id`, `bowling_team_id`) may be encoded causally in downstream feature pipelines.
  2. **`model_feature`**: Strictly causal live state, context, or delivery-resolution signal permissible as input to the Win Probability Engine (`post_delivery` `*_after` state + safe pre-match/ball context). Zero future-ball or post-match dependency.
  3. **`regime_or_audit_metadata`**: Regime classifications, pre-delivery audit transition pairs (`*_before`), raw unnormalized variants, data-quality flags, ambiguity indicators, display-only strings, and training eligibility gates. **Strictly forbidden as predictive model inputs** (unless an explicit non-outcome structural indicator is promoted under `model_feature`).
  4. **`target`**: Supervised Win Probability ground-truth labels derived exclusively from `matches.win_team_id`.
